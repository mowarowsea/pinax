# pinax — アーキテクチャ設計書

## 1. 三本柱の中の pinax

自宅の 3 つのサービスは「相手には原理的に持てない情報」で切ってある。pinax はその 3 本目。

| | 持っている情報 | 持てない情報 |
|---|---|---|
| **DryEyes** | 前回スナップショット、既読位置、XPath、監視の文脈 | どのホスターなら落とせるか / もう持っているか |
| **PowerDowner** | ホスター実績表、エンジン振り分け、リトライ、保存先 | そのページで何が「新しい」のか |
| **pinax** | **手元の棚に何があるか**、欠番、完結、書誌と書影 | どこから落とすか / 何が新しく出たか |

```
DryEyes                     PowerDowner                    pinax
何が「新しい」のか      →    どう「落とす」のか       →    何を「持っている」のか
                             ← 「これ持ってる?」 ────────┘
```

**pinax は落とさないし、探さない。** 棚を見て答えるだけ。

## 2. なぜ pinax を立てるのか

今 PowerDowner が `items` 表 (取得済み台帳) を持っていて、DryEyes から投入が来ると
「もう持っているか」を自分で判定している。それには 2 つ無理がある。

1. **台帳はダウンロードの記録であって、棚の姿ではない。** 手で NAS に置いたもの、
   落とす前から持っていたもの、消したものが台帳に反映されない。
   PowerDowner の README にもある通り「間違った行が 1 つあるだけでその巻は永久に落ちてこない」
2. **蔵書そのものを見たい要求に応えられない。** 表紙を並べる、欠番を探す、手元へ落とす —
   これはダウンローダの仕事ではない

pinax は**ファイルそのものを正**にする。台帳を信じるのではなく、棚を毎回読む。

## 3. データの持ち方

```
series (作品)  ─┬─ volumes (巻)  ─── files (実ファイル)
                └─ covers / bib (外から取った書影と書誌)
```

### 作品の単位はフォルダ

`series` の一意キーは `(root_id, folder)`。**`series_key` ではない。**

蔵書は作品ごとにフォルダで分けてある。「同じフォルダに入っている = 同じ作品」は
人が既に下した判断で、ファイル名より強い。実物で確かめた通り、ファイル名を正にすると割れる:

```
[おがきちか] Landreaall/[おがきちか] Landreaall ランドリオール 第37巻.rar
  → 副題の有無で landreaall と landreaallランドリオール の 2 作品になる
```

一方 `series_key` (= `seriesKeyOf(title)`) は**同一性の判定にだけ使う別軸**で、一意ではない。
`[BETEMIUS] 同人誌` と `[河内和泉] 同人誌` は同じキーだが別の棚になる。

**この 2 つを 1 本にまとめてはいけない。** 用途が違う:

| | 使うところ | 一意か |
|---|---|---|
| `folder` | 棚としての作品。画面に並ぶ単位 | 根の中で一意 |
| `series_key` | 外から「作品名」だけで所持を聞かれた時の突き合わせ | 一意でない |

### 巻とファイルを分ける

1 巻に複数のファイルがぶら下がる。分割書庫 (`.part1` / `.r00`) と、同じ巻の別版 (`[LQ]`) の
両方があるため。`files.volume_id` が null なら「巻数を読めなかったファイル」で、
欠番の計算には参加しないが作品には属する。

### 消えたものを消さない

スキャンで見なかったファイルは `present = 0` に倒すだけで行は残す。
**根が丸ごと読めない時はスキャン自体を中止する** — NAS が一時的に見えないだけの時に
蔵書がまるごと消えると、所持判定が「持っていない」に化けて全巻を落とし直すことになる。

## 4. PowerDowner との互換

**`seriesKeyOf` は PowerDowner の `src/volume.ts` と同一でなければならない。**

pinax の `src/volume.ts` はあちらからの移植で、足したのは完結マークの扱いだけ
(`stripCompletionMark`)。片方だけ直すと、向こうが「持っている」と言った巻を
こちらが「持っていない」と言い、静かに二重取得が始まる。

一方 `src/naming.ts` は**読み戻し専用**にしてある。組み立て (リネーム) 側は今は
PowerDowner にある。Z: の受け入れトレイを整理する段になったら、あちらの
`planName` / `fitPath` / `uniqueName` をここへ引き取る — 書く側と読む側が別々の規則を
持った瞬間に、自分で置いたファイルを自分で見つけられなくなる。

### 問い合わせの入り口では寛容にする

`/api/own` は DryEyes が送ってくる**抽出前の生テキスト**も受ける。
`[つくしあきひと] メイドインアビス 第03巻` の形で届くので、先頭の `[著者]` を
`parseFilename` で落としてからキーにする。落とさないと
`つくしあきひとメイドインアビス` になり、蔵書側の `メイドインアビス` と一生噛み合わない。

**落とす仕事は naming.ts に任せること。** 蔵書のファイル名を読むのと同じ関数を通すのが肝で、
`seriesKeyOf` そのものには手を入れていないので PowerDowner との互換は保たれる。

## 5. 外の世界との境目

**pinax から外へ出る問い合わせは `src/bib/cache.ts` の 1 本だけを通る。**
これがプロジェクトのテーマ ("Never burn. Remember Alexandria.") をそのまま形にした部分。

```
                        ┌──────────────────────────┐
  作品 ─▶ ndl.ts ──────▶│  cache.ts (唯一の窓口)   │──▶ 外部 API
                        │  ・生のまま焼き付ける      │
  他サービス ─▶ /api/bib/proxy ─▶│ ・期限切れでも捨てない │
                        │  ・提供元ごとに間引く      │
                        └──────────────────────────┘
                                    │
                            data/pinax.db (http_cache)
                            data/covers/  (焼いた書影)
```

- **期限切れのキャッシュを捨てない。** 外が落ちている時に古い値を返せることが値打ちで、
  「新しくないから何も返さない」が一番やってはいけない振る舞い。`stale` の印を付けて返す
- **書影はファイルとして焼く。** 名前は中身の SHA-256 なので、同じ画像は 1 つで済み、
  URL は永久に変わらない (`Cache-Control: immutable` を付けられる)
- **提供元を足すのはアダプタ 1 枚。** 楽天ブックスを足す時は `src/bib/rakuten.ts` を書いて
  `enrich.ts` の経路に挟むだけ。cache.ts には触らない

### 提供元の実力 (2026-09-12 実測)

| 提供元 | 書誌 | 書影 | キー登録 |
|---|---|---|---|
| **NDLサーチ** | 巻ごとの ISBN が取れる。著者を添えれば精度が高い | ISBN のうち約半分 | 不要 |
| openBD | ISBN 起点でしか引けない | **0 件。使えない** | 不要 |
| Google Books | — | — | 実質必須 (キー無しは 429) |
| 楽天ブックス | 未検証 (これから) | 期待できる | アプリ ID が要る |

## 6. 通知の担当

**PowerDowner と二重に鳴らさない。**

| 出来事 | 出すのは |
|---|---|
| 監視先に新着が出た / 候補が溜まった | DryEyes |
| ジョブの完了・人間待ち・失敗 | PowerDowner |
| **棚に増えた・完結した** | **pinax** |

「ダウンロードが終わった」は PowerDowner が出す。pinax が出すのは棚の変化だけ。
落として棚に入れば両方鳴るが、意味が違う (片方は「落ちた」、片方は「蔵書が増えた」)。

**画面のお知らせと通知は別物。** お知らせ (`events` 表) には必ず残し、通知は出せたら出す。
ntfy が落ちていても新着が消えないようにするため。届かなかったものは印を付けず、次の巡回で試し直す。

## 7. LocalLauncher との関係

```yaml
  - id: pinax
    name: pinax
    description: 漫画の蔵書カタログ（Never burn. Remember Alexandria.）
    command: "start.bat"
    cwd: "C:/Users/seamo/pinax"
    url: "http://100.121.83.66:3838/"
    health_url: "http://127.0.0.1:3838/api/health"
    require_url: true
    icon: "📕"
    profiles: [mowa]
```

守るべき前提 (PowerDowner と同じ):

- **フォアグラウンドで走り続けること。** デーモン化して即 return すると生死を見失われる
- **SIGINT / SIGTERM で片付けること** (`src/index.ts` の `shutdown`)
- **対話的な入力を求めないこと。** 初回も含めて全部 `config.json` で済ませる
- `GET /api/health` は pinax 自体が生きていれば 200。棚の件数とキャッシュの様子も返すので、
  画面を見なくても様子が分かる

## 8. これから

### 8.1 受け入れトレイ (Z:) を棚へ入れる

`Z:\90_新悟スペース\JDownLoaderダウンロード` に **3063 個の生ファイルが平置き**されている。

```
100man no Inochi no ue ni ore v15-16s.rar
1nenAguminoMonster_01s.rar.rar
12ninin_no_Miko_06.rar
```

ローマ字・区切りばらばら・拡張子の二重付け。**蔵書と同じ顔で並べてはいけない** ので、
`roots[].kind = "inbox"` として別扱いにする器だけ先に用意してある。

やること:

1. inbox を読んで「これは○○の第15-16巻では?」と**提案**する。
   ローマ字と日本語を繋ぐ手掛かりは 2 つ — 既にある蔵書 485 作品の読み (NDL の
   `dcndl:titleTranscription` が取れる) と、ファイル名の巻数
2. 人が承認したら、`[著者] 作品名/[著者] 作品名 第nn巻.rar` へ整理して NAS へ移す
3. **提案を自動で実行しない。** 3063 件を機械が黙って動かして間違えると、
   どれが元どこにあったか分からなくなる

この段で PowerDowner の `planName` / `fitPath` / `uniqueName` を引き取る。

### 8.2 PowerDowner の台帳を引き取る

今の PowerDowner:

```
DryEyes ──▶ POST /api/jobs ──▶ PowerDowner ──▶ items 表を自分で見て所持判定
```

寄せた後:

```
DryEyes ──▶ POST /api/jobs ──▶ PowerDowner ──▶ POST /api/own (pinax) ──▶ 棚を見て答える
```

**一息にやらないこと。** PowerDowner の README にある通り、台帳は
「間違った行が 1 つあるだけでその巻を永久に落とせなくする」場所。段を踏む:

1. **影運転。** PowerDowner は今まで通り自分の `items` で判定しつつ、pinax にも聞いて
   **答えが食い違った件だけログに出す**。しばらく回して差分の正体を見る
2. 差分が説明できる状態になったら、判定を pinax へ寄せる
3. `items` 表は**消さない**。ダウンロードの履歴としては意味があるし、
   戻せる道を残しておく

食い違いが出る理由は先に分かっている:

- pinax は**ファイルを正**にするので、手で置いたものも消したものも反映される (これが目的)
- 巻数を読めない行の扱い。両方「持っていない」に倒すので落とし直しは起きるが、
  取りこぼしは起きない
- PowerDowner の台帳はユーザー単位だが、pinax の棚は**根 (フォルダ) 単位**。
  ユーザーごとに棚を分けたいなら `roots` を分ける

### 8.3 サジェスト (外部 API の汎用キャッシュプロキシ)

`/api/bib/search` と `/api/bib/proxy` で口は開けてある。これから足すもの:

- **作品名のオートコンプリート。** PowerDowner の「作品として登録する」欄や
  DryEyes の投入設定で作品名を打つと、pinax の蔵書 + 書誌キャッシュから候補が出る。
  表記ゆれ (ローマ字・略称・副題の有無) も吸えるとよい
- 楽天ブックスのアダプタ。表紙の取得率を上げる本命

### 8.4 その他

- 複数の根 (NAS を増やした時) の重複検出。今は `同じ作品が複数フォルダに散っている`
  状態を probe が見つけるだけで、画面には出していない。実物に 3 件ある
  (`掟上今日子の備忘録`、`ワンパンマン` が著者違いのフォルダで 2 つずつ)
- 巻をまとめて落とす (今は 1 ファイルずつ)。分割書庫は zip に包む必要がある
- 読んだ / 読んでいないの記録。今は「持っている / いない」しか無い
