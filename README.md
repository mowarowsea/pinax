# pinax

> "pinax" is book manager. **Never burn. Remember Alexandria.**

NAS に積んである漫画の蔵書を、**何を持っていて何を持っていないか**が一目で分かる形にする
自宅用のカタログ。名前はアレクサンドリア図書館の蔵書目録『ピナケス』(Πίνακες) から。

```
NAS の棚 ──▶ スキャン ──▶ カタログ (SQLite) ──┬─▶ 表紙付きの一覧 (Web)
                                              ├─▶ 欠番の割り出し
                                              ├─▶ 所持の問い合わせ API (PowerDowner / DryEyes 向け)
                                              ├─▶ ダウンロード (Web から手元へ)
                                              └─▶ 新着のお知らせ + ntfy 通知
```

- Node.js 24 以上だけあれば動く。SQLite は Node 内蔵のものを使う
- 書誌と書影は**国立国会図書館サーチ**から取り、**ローカルに焼き付ける**。
  一度取ったものは二度と外に聞かない。外部サービスが消えてもカタログは残る
- 画面は素の HTML/JS。ビルド不要

## 立ち上げ

```bash
npm install
cp config.example.json config.json   # roots に自分の棚を書く
npm start                            # http://localhost:3838
```

`config.json` の `roots` に蔵書のフォルダを並べる。UNC パスをそのまま書ける。

```json
{
  "roots": [
    { "id": "nas", "label": "NAS 蔵書", "path": "\\\\192.168.3.30\\disk1_pt1\\manga", "kind": "shelf" }
  ]
}
```

| キー | 既定 | 意味 |
|---|---|---|
| `port` / `host` | `3838` / `0.0.0.0` | 待ち受け |
| `apiToken` | 空 | `/api/own` を叩く時の共有トークン。空なら認証なし |
| `roots[].kind` | `shelf` | `shelf` は整理済みの蔵書、`inbox` は受け入れトレイ (下記) |
| `scan.onStart` | `true` | 起動時に 1 回スキャンする |
| `scan.intervalMinutes` | `60` | 定期スキャンの間隔。`0` で止まる |
| `bib.ttlDays` | `90` | 書誌キャッシュの寿命。**切れても捨てない** |
| `bib.minIntervalMs` | `1200` | 外部 API を叩く最低間隔 |
| `notify.ntfyUrl` | 空 | 新着の通知先。空でも画面のお知らせには残る |

## 蔵書の並び方

pinax が読めるのはこの形:

```
{蔵書ルート}/[{著者}] {作品名}/[{著者}] {作品名} 第{nn}巻.{拡張子}
                              [{著者}] {作品名} 第{nn}-{nn}巻.{拡張子}   ← 範囲もの
```

最終巻には `(完)` が付く。**フォルダ名とファイル名のどちらに付いていてもよい。**

### 実物に合わせて読めるようにしてあるもの

手元の 488 作品 4945 ファイルに当てて確かめた (2026-09-12)。**巻数を読めたのは 98.5%**。

| 実物 | 読み方 |
|---|---|
| `[Boichi] ORIGIN -オリジン-(完)/…第03巻.rar` | 完結マークはフォルダにもファイルにも付く。両方落としてからキーにする |
| `…第04巻 [LQ].rar` / `…第09巻w.rar` | 巻数の後ろの版・品質の印。巻としては同じものとして扱い、表示にだけ回す |
| `[岩明均×室井大資] レイリ` | 共著。著者としてはそのまま持つが、同一性のキーには入れない |
| `[おがきちか] Landreaall/…Landreaall ランドリオール 第37巻.rar` | **作品の素性はフォルダを正とする**。ファイル名の副題の揺れで作品が割れないように |
| `[ゆうきまさみ] 機動警察パトレイバー(完)/(一般コミック) […] 第06巻.rar` | 同上。ファイル名の頭のゴミはフォルダが救う |
| `[井上堅二×吉岡公威] ぐらんぶる/… ぐらんぶる 01.rar` | 単位の無い巻数。**フォルダ名を前置きとして剥がせた時だけ**巻数と読む |
| `…第03巻.part2.rar` / `…第03巻.r00` | 分割書庫。1 巻に複数ファイルがぶら下がる形で持つ |

**作品の単位はフォルダ。** `[BETEMIUS] 同人誌` と `[河内和泉] 同人誌` は同じ作品名だが
別の棚なので、別の作品として並ぶ。

## 画面

| ところ | できること |
|---|---|
| ヘッダ | 作品数・冊数・焼いた表紙の数。棚の読み直し、表紙の取得を手で進める |
| お知らせ | 新しく入った作品・増えた巻・完結。既読にできる |
| 絞り込み | 作品名/著者の検索、**欠番あり**、完結 / 継続中、表紙なし |
| 作品を開く | 巻を数直線に並べる。**持っていない巻は破線の枠で穴として見える**。各巻から保存 |

## 欠番の数え方

**1 巻から手持ちの最大巻までの間で抜けている番号**を欠番と呼ぶ。最大巻の先 (まだ出ていない巻)
は数えない — 「持っていない」のではなく「まだ無い」ので。

**巻と話は別々の数直線で数える。** 混ぜると、第224話を持っている作品が
「224 巻まであるのに 40 巻しか無い」ことになる。

巻数を読めなかったファイルは欠番の計算に参加しない。持ってはいるので作品には属し、
画面では「巻数を読めなかったファイル」として別に並ぶ。

## 所持の問い合わせ API

PowerDowner や DryEyes が「この巻もう持ってる?」と聞きに来る口。

```
POST /api/own
Authorization: Bearer <apiToken>      # config の apiToken が空なら不要
Content-Type: application/json

{ "items": [ { "title": "作品名", "author": "著者", "volume": "3", "rawText": "[著者] 作品名 第03巻" } ] }
```

```json
{ "answers": [ {
  "parsed":  { "seriesKey": "…", "volumeFrom": 3, "volumeTo": 3 },
  "owned":   true,
  "missing": [],
  "series":  [ { "id": 12, "label": "[著者] 作品名", "folder": "…", "completed": false } ],
  "reason":  "所持済み (第3巻)"
} ] }
```

押さえておくこと:

- **巻数を読めない問い合わせには「持っていない」と答える。** 黙って持っていることに
  すると、その巻が永久に落ちてこない。もう一度落ちる方が被害が小さい
- **未所持の巻が 1 つでも残るなら `owned` は false。** 1-3 を持っている状態で 2-5 が
  来たら 4,5 が残るので落とす。ファイルを巻単位で切れない以上こうするしかない
- **著者は同一性のキーに入れない。** 入れると、`title` だけ送ってくる相手と噛み合わない
- `parsed` を返しているのは、食い違った時に**どう読んだか**を向こうから追えるようにするため

## 書誌と表紙

```
[著者] 作品名 ──▶ NDLサーチ OpenSearch (title + creator + mediatype=books)
              ──▶ 巻ごとの ISBN
              ──▶ NDL サムネイル /thumbnail/{ISBN}.jpg
              ──▶ data/covers/ へ焼く
```

蔵書のフォルダ名が著者を持っているので、**著者付きで引ける**のが効く。著者無しだと
CD・DVD・アンソロジーが混ざって使い物にならない。

実測 (2026-09-12):

| | 結果 |
|---|---|
| NDL で ISBN が取れた巻 | 約 7 割 |
| そのうち NDL に書影があった | 約 5 割 |
| **結果として表紙が付く巻** | **約 3.5 割** |

残りは NDL に書影が無い。埋めるなら**楽天ブックス API** を足すのが早い
(アプリ ID の登録が要る)。`src/bib/` にアダプタを 1 枚足すだけで済むようにしてある。

### 外部 API は全部キャッシュを通る

`src/bib/cache.ts` が唯一の窓口。

- 応答は**生のまま**焼き付ける。解釈を後から直せるようにするため
- **期限切れでも捨てない。** 外が落ちている時に古い値を返せることが値打ちで、
  「新しくないから何も返さない」が一番やってはいけない振る舞い
- 提供元ごとに直列 + 最低間隔。500 作品ぶんを一息に叩いて締め出されたら、
  その時点で蔵書の表紙は永久に埋まらない

他のサービスからもこのキャッシュを使える:

```
GET /api/bib/search?title=作品名&author=著者      書誌の検索 (キャッシュ越し)
GET /api/bib/proxy?url=<許可した提供元の URL>     生の中継 (要トークン)
```

`/api/bib/proxy` が中継するのは設定で許した提供元だけ。任意の URL を中継する踏み台にはしない。

### 落とし穴

- **NDL のサムネイルは `Referer` が無いと 403 を返す。** UA は何を名乗っても関係ない。
  ここを落とすと表紙が 1 枚も焼けないまま「取れなかった」とだけ記録されて原因が見えない
- **openBD は書影を持っていない。** 漫画 100 冊ぶんの ISBN で試したところ、データは
  85 件返るのに `summary.cover` は 0 件だった。書誌の補完には使えるが表紙の供給源にはならない
- **合作の著者をそのまま NDL に渡すと 0 件になる。** `[山川直輝×奈央晃徳]` のような
  丸ごとの文字列は当たらないので、区切って 1 人ずつ試す (`authorVariants`)
- **NDL は読みを書名に差し込む** ことがある (`恋愛ラボ` → `恋愛 (ラブ) ラボ`)。
  括弧の中身を落とした形でも突き合わせる
- **一度聞きに行った作品には印を押す** (`series.enriched_at`)。「表紙が無い作品」を
  選び直す作りにすると、NDL に書影が無い作品が先頭に居座って後ろまで進まない

## API 一覧

```
GET    /api/health                      死活監視 (LocalLauncher 用)。件数とキャッシュの様子も返す
GET    /api/series?q=&gaps=&completed=&needsCover=&sort=&limit=&offset=
GET    /api/series/:id                  巻・ファイル・書誌つきの詳細
POST   /api/series/:id/enrich           書誌と表紙を取り直す
POST   /api/own                         所持の問い合わせ (要トークン)
GET    /api/events?unread=1             お知らせ
POST   /api/events/read                 既読にする
POST   /api/scan                        棚の読み直し ({ root } で 1 つだけ)
POST   /api/covers/fill                 表紙の無い作品を少しずつ埋める
GET    /api/covers/:id                  焼いた表紙
GET    /api/files/:id/download          実ファイルを落とす
GET    /api/bib/search?title=&author=   書誌の検索 (キャッシュ越し)
GET    /api/bib/proxy?url=              許可した提供元への生の中継 (要トークン)
```

## 運用メモ

- **NAS が見えない時はスキャンを中止する。** 蔵書を「消えた」に倒さない。倒すと
  所持判定が「持っていない」に化けて、全巻を落とし直すことになる
- 消えたファイルの行は消さず `present` を 0 にするだけ。履歴が残る
- **初回のスキャンはお知らせを出さない。** 488 作品の登録が全部新着として流れてくると
  本物の新着が埋もれる。最初は棚卸しとして静かに済ませる
- 新刊のお知らせは作品ごとに 1 件にまとめる。分割書庫で 5 通も飛ばさないため
- 表紙は 5 分ごとに数作品ずつ埋まる。進み具合は `covers` 表と `series.enriched_at`
  そのものが持つので、落ちても次の起動から続きになる
- **通知と画面のお知らせは別物。** お知らせには必ず残し、通知は出せたら出す。
  ntfy が落ちていても新着が消えないように
